# TakeTicket

**TakeTicket** — это продвинутая бэкенд-система бронирования билетов (аналог Яндекс.Афиши или Kassir.ru), разрабатываемая с нуля до уровня BigTech-архитектуры. 
В своей финальной версии проект представляет собой высоконагруженную микросервисную архитектуру, которая решает реальные инженерные проблемы: предотвращает двойное бронирование (race conditions) с помощью распределенных блокировок (Distributed Locks) и поддерживает асинхронные потоки уведомлений.

**Целевой технический стек финальной версии:**
* **Язык и Фреймворк:** Java Core, Spring Boot, Spring Data JPA, Spring Security
* **Базы данных и кэш:** PostgreSQL, Redis
* **Интеграции и брокеры:** Apache Kafka, gRPC
* **Архитектура:** Микросервисы (Microservices), REST API
* **Инфраструктура:** Docker, CI/CD

## Дорожная карта (Roadmap)

Проект разбит на небольшие итерации для плавного перехода от консольного приложения к распределенной системе.

### Этап 1: Ядро и бизнес-логика (Чистая Java) 🟢
- [x] Спроектировать доменную модель (`Event`, `Hall`, `Seat`, `Status`).
- [x] Реализовать базовую бизнес-логику бронирования (`EventService`).
- [x] Создать интерактивное консольное меню (CLI).
- [x] Реализовать обработку ошибок через кастомные исключения.

### Этап 2: Сохранение состояния (File I/O) 🟡
- [ ] Настроить запись купленных билетов в CSV-файл при бронировании (try-with-resources).
- [ ] Реализовать чтение CSV-файла при старте приложения для восстановления состояния залов.
- [ ] Применить Stream API для удобного парсинга данных.

### Этап 3: Реляционная база данных (PostgreSQL + JDBC) ⚪
- [ ] Установить PostgreSQL и спроектировать схему БД (таблицы, связи, индексы).
- [ ] Отказаться от файлов в пользу БД. Подключить чистый JDBC.
- [ ] Реализовать базовые CRUD-операции через SQL-запросы в коде.

### Этап 4: Spring Boot и REST API (Монолит) ⚪
- [ ] Перенести бизнес-логику в проект Spring Boot.
- [ ] Удалить консольное меню (Scanner) и заменить его на REST-контроллеры.
- [ ] Заменить чистый JDBC на Spring Data JPA (Hibernate).
- [ ] Добавить базовую авторизацию и регистрацию (Spring Security).
- [ ] Внедрить Swagger/OpenAPI для документирования эндпоинтов.

### Этап 5: Продвинутые паттерны (Блокировки и Кэш) ⚪
- [ ] Развернуть Redis.
- [ ] Реализовать Distributed Lock для решения проблемы двойного бронирования (race condition).
- [ ] Добавить динамическое ценообразование в зависимости от количества оставшихся мест.

### Этап 6: Микросервисы и Асинхронность ⚪
- [ ] Распилить монолит: вынести логику генерации и отправки билетов в отдельный "Сервис Уведомлений".
- [ ] Настроить асинхронное общение сервисов через Apache Kafka.
- [ ] Настроить синхронные вызовы между внутренними микросервисами через gRPC.

### Этап 7: Инфраструктура (DevOps) ⚪
- [ ] Упаковать все сервисы и базы данных в Docker-контейнеры (Docker Compose).
- [ ] Настроить базовый CI/CD pipeline (например, GitHub Actions).

## Как запустить (Для текущей версии)
1. Склонируйте репозиторий.
2. Откройте проект в IntelliJ IDEA.
3. Убедитесь, что используется Java 16+ (лично я использую 21.0.12).
4. Запустите класс `Main.java`.
5. Следуйте инструкциям в интерактивном консольном меню.
